# 关键设计决策

本文件记录对后续维护有约束力的技术选择。改变这些选择前，应说明迁移方式、补充测试并更新本文件。

## D-001：使用精确整数分数

JavaScript 浮点数无法精确表示三分之一等值。所有游戏运算使用约分后的整数分子和分母，最终通过 `numerator === 24 * denominator` 判定，避免正确答案被浮点误差拒绝。

## D-002：解析结构化 token，不执行字符串

用户只能点击卡片、运算符和括号生成 `ExpressionToken`。表达式使用中缀转后缀后求值，不使用 `eval` 或动态函数，因此数字来源和可用语法可控。

## D-003：重复数字通过卡片 ID 区分

题目允许出现相同数值。数字 token 保存唯一 `cardId`，答案验证检查四个实例各使用一次，而不是只统计数值。

## D-004：静态提交有解题库

构建仓库中保存由脚本生成的 `puzzle-bank.json`，应用运行时直接随机抽题，避免首次启动枚举全部组合。题库属于需要提交的生成文件，只能通过 npm 脚本更新。

## D-005：题库生成器保持独立

生成器使用无 TypeScript 运行器依赖的 Node.js 脚本，确保干净安装后可直接运行。代价是它与运行时求解器存在少量重复；当前规模下通过算法测试和 `check:puzzles` 防止漂移，暂不为消除重复引入构建工具或大重构。

## D-006：统计使用版本化 localStorage

第一阶段没有后端。统计保存于 `make24:stats`，数据结构显式使用 `version: 1`，损坏或未知版本安全回退到默认值。任何结构变化都必须考虑现有浏览器数据兼容。

## D-007：无后端的可安装 PWA

Manifest、Service Worker、图标和离线缓存由 `vite-plugin-pwa` 生成。更新采用提示模式，不在玩家进行一题时自动刷新。

## D-008：npm 是唯一包管理器

项目以 `package-lock.json` 和 `npm ci` 作为可重复安装基线。保留多套锁文件会产生不同依赖树，因此不接受 pnpm、Yarn 或 Bun 锁文件与 npm 锁文件并存。

## D-009：保持小型 React 架构

当前应用使用 React 内置状态和普通组件即可满足需求。除非出现明确复杂度或产品要求，不引入路由、Redux、后端 SDK 或大型 UI 框架，也不为了形式拆分 `App.tsx`。
